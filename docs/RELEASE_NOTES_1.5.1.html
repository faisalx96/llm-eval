▰Datasets in qym

  • Dataset Management: Create, upload, edit, and download datasets from the dashboard.
  • Dataset Versioning: Create drafts, publish versions, and choose the production version.
  • Version Comparison: Compare versions to see added, removed, and changed items.

  • Trace-Aware Analysis: The analyzer now uses LLM messages, reasoning, tool calls, tool results, and errors from traces to find the cause of failures.
  • Root Cause Aggregation: After the analyzer finishes, qym groups similar root causes into consistent categories.
  • Multi-Metric Analysis: Analyze several metrics with a separate diagnosis for each.

  • Metric Correlations: See which metrics move together or trade off.
  • Quality–Latency Frontier: Find fast, high-quality items and slow failures.
  • Quality–Stability Map: Identify strong items and results that fluctuate.
  • Confidence Intervals: See the uncertainty around repeat-run results.

›_SDK — new features

These changes apply to your evaluation scripts.

Native datasets with QymDataset

Pass a dataset name directly to Evaluator to use its current production version. Import QymDataset when you need an exact version or a different alias.

Example
from qym import Evaluator, QymDataset

# String name: uses the current production version
production_dataset = "qa-set"

# Select an exact version
v3_dataset = QymDataset("qa-set", version="v3")

# Or select another named alias
staging_dataset = QymDataset("qa-set", alias="staging")

result = Evaluator(
    task=my_task,
    dataset=v3_dataset,
    metrics=["exact_match"],
).run()

Repeat runs with samples

Add samples=n to Evaluator. qym repeats every dataset item inside one run, stores every pass, and calculates reliability results automatically.

Example
from qym import Evaluator

result = Evaluator(
    task=my_task,
    dataset="qa-set",
    metrics=["exact_match"],
    samples=5,
).run()

stats = result.group_stats()
print(stats["pass_at_k"])
print(stats["reliability"])

Multiple inputs and judge fields with CsvDataset

Pass several CSV columns to your task and metrics. Use input_mapping when column names differ from the fields your task or LLM judge expects. Missing judge fields are now caught before a model call.

Example
from qym import CsvDataset, Evaluator

def my_task(question, context):
    return answer_question(question, context)

dataset = CsvDataset(
    "rag-eval.csv",
    input_col=["prompt", "retrieved_context"],
    expected_col="expected_answer",
)

result = Evaluator(
    task=my_task,
    dataset=dataset,
    metrics=["faithfulness_llm"],
    input_mapping={
        "prompt": "question",
        "retrieved_context": "context",
    },
).run()

Task metadata and typed custom metrics

Return qym’s output and metadata dictionary when a metric needs supporting task context. Then import the new Metric class to define how qym validates, passes, and displays that metric.

Example
from qym import Metric

def my_task(question):
    answer, sources = answer_question(question)
    return {
        "output": answer,
        "metadata": {"sources": sources},
    }

def source_score(output, expected):
    return check_sources(
        output["output"],
        output["metadata"]["sources"],
    )

source_metric = Metric(
    source_score,
    name="source_quality",
    score_type="percentage",
    pass_threshold=0.8,
)

⚠Changes you must make

1Install SDK 1.5.1

Install
pip install qym==1.5.1

2Update your .env file

Replace QYM_PLATFORM_URL with QYM_BASE_URL. Keep QYM_API_KEY as it is.

Before · .env
QYM_PLATFORM_URL=https://qym.example
QYM_API_KEY=your-api-key
After · .env
QYM_BASE_URL=https://qym.example
QYM_API_KEY=your-api-key

3Move datasets out of Langfuse

qym no longer loads Langfuse datasets. Upload shared datasets to qym, or use CsvDataset or JsonlDataset for local data.

4Update dictionary outputs and custom metrics

Plain values still work. If a task returns a dictionary, it must contain exactly output and metadata.

Before · task
return {
    "answer": answer,
    "sources": sources,
}
After · task
return {
    "output": answer,
    "metadata": {"sources": sources},
}

Update custom metrics too. A custom metric receives the full dictionary. Read the answer from output["output"] and task data from output["metadata"].

Custom metric
def source_metric(output, expected):
    answer = output["output"]
    sources = output["metadata"]["sources"]
    return check_sources(answer, sources)

5Use samples for repeats

If the same run configuration was repeated several times, replace it with one Evaluator(...).run() call.

Before
results = Evaluator.run_parallel(
    runs=[{
        "task": my_task,
        "dataset": "qa-set",
        "metrics": ["exact_match"],
    }] * 3,
)
After
result = Evaluator(
    task=my_task,
    dataset="qa-set",
    metrics=["exact_match"],
    samples=3,
).run()

Keep run_parallel when the run configurations are different.

After updating: run qym config check --json to confirm the platform address and API key. Full guidance is available under Docs in qym.
