SDK GUIDE

Repeat runs & pass@k

LLMs are stochastic — the same item can pass on one try and fail on the next, so a single run tells you very little about consistency. samples=k evaluates every dataset item k times inside ONE run and reports the group metrics (Pass@k, Pass^k, Avg@k, Max@k, Consistency, Reliability) automatically, with confidence intervals on every mean.

One parameter, one run. Before samples=, pass@k meant launching k duplicate runs and grouping them afterwards. That pattern is now deprecated — the SDK warns when it detects duplicate run specs. One samples=k run produces one dashboard row, one checkpoint file, and every group metric.

Quick start

from qym import Evaluator

result = Evaluator(
    task=my_task,
    dataset="my-dataset",
    metrics=["correctness"],
    samples=8,                    # evaluate every item 8 times
).run()

stats = result.get_metric_stats("correctness")
print(stats["mean"])                          # 0.61 - mean score per attempt
print(stats["ci_low"], stats["ci_high"])      # 0.55 0.67 - bootstrap 95% CI

print(result.group_stats())
# {"k": 8, "pass_at_k": 0.93, "pass_hat_k": 0.34, "avg_at_k": 0.61,
#  "max_at_k": 0.78, "consistency": 0.71, "reliability": 0.68, ...}

print(result.pass_at(3))                      # 0.84 - ANY of 3 tries passes
print(result.pass_hat(3))                     # 0.41 - ALL 3 tries pass

Also available on the CLI (--samples 8) and as a "samples": 8 key on multi-run config entries.

How it executes

The dataset runs as k sequential passes: every item completes pass 1, then pass 1's metrics are final, then pass 2 starts — the same progressive rhythm as watching a group of runs finish, inside one run. The terminal dashboard shows pass 2/8 progress, and the checkpoint stores one CSV row per item × pass, so an interrupted run resumes exactly where it stopped (mid-pass).

Retries are unchanged: max_retries still recovers failures within a pass. A pass that exhausts its retries scores 0 for that pass — which is exactly what makes Pass^k an honest reliability number.

The group metrics

Same names and formulas as the platform's group analysis, with k = samples. Pass/fail uses the standard threshold score >= 0.8 (override per call).

MetricQuestion it answers
Pass@kDid at least one of the k passes succeed? (capability — "can it ever?")
Pass^kDid all k passes succeed? (reliability — "will it every time?")
Avg@kMean score over every pass.
Max@kMean of each item's best pass.
ConsistencyDo the k passes agree with each other?
ReliabilityFor solvable items, how often do they pass?

Read both Pass@k and Pass^k. They diverge hard: at a 70% per-try pass rate, Pass@3 ≈ 0.97 but Pass^3 ≈ 0.34. Showing only Pass@k flatters a flaky system; Pass^k is the production number.

Any k, after the fact

All passes are stored, so result.pass_at(k) / result.pass_hat(k) work for any k ≤ samples without re-running — one samples=10 run yields the entire accuracy-vs-k curve. For k < samples these use the unbiased combinatorial estimator (1 - C(n-c,k)/C(n,k), the Codex/HumanEval standard); at k = samples they equal the observed group metrics.

result = Evaluator(task, dataset, metrics=["correctness"], samples=10).run()

for k in range(1, 11):
    print(k, round(result.pass_at(k), 3))     # the whole curve, one run

Requirements & caveats

  • Temperature must be > 0. A deterministic task returns the same output every pass; qym detects byte-identical passes and warns that repeat metrics measure nothing.
  • Stable item IDs matter as always — passes align by item identity.
  • Cost scales with k: samples=8 means 8× the task calls (metrics run per pass too).
