# App Troubleshooting

Use this page when something looks wrong in the deployed qym app.

## Missing run

Check:

- whether you are in the correct organization or project;
- whether filters hide the run;
- whether the run belongs to another owner, task, or date range;
- whether your role allows you to view that project;
- whether a teammate has a direct run link.

If the run still does not appear, send the run name, project, approximate time, and owner to the team that launched it.

## Stale progress

A run can look stale when the launching process is still working, disconnected, or failed before sending final status.

Check:

- last updated time;
- whether item rows are still arriving;
- whether the run has errors or warnings;
- whether another run from the same source completed recently.

Ask the run owner or platform operator to inspect the launcher or ingestion logs if the status does not change.

## Cannot approve or reject

Check:

- whether the run is in a reviewable state;
- whether you have the right role for the project;
- whether the run belongs to your team or organization scope;
- whether your session needs to be refreshed.

## Trace or item data is missing

Not every run includes traces or rich item metadata. The app displays the evidence it received from the evaluation. Ask the developer who owns the run whether tracing and item metadata were enabled for that workflow.

## Access denied

If you can sign in but cannot see expected content, collect:

- your email or username;
- organization and project name;
- the run link or expected run name;
- the action you were trying to perform;
- a screenshot of the access message.

Send that information to your qym administrator.
