# Getting Started In The App

Use this page when qym is already deployed and you have a browser login or an app link from your team.

## First visit checklist

1. Sign in through your organization's configured login flow.
2. Confirm you are in the expected organization or project context.
3. Open the runs view.
4. Filter to the task, dataset, model, owner, or date range you care about.
5. Open the newest relevant run and inspect its status, total item count, aggregate metrics, and failed items.

## Main app areas

| Area | Use it for |
|------|------------|
| Runs | Browse evaluations, status, owners, models, metrics, and timestamps. |
| Run detail | Inspect item rows, outputs, expected values, metric scores, errors, traces, and metadata. |
| Compare | Compare two or more runs to identify regressions and improvements. |
| Analysis | Review generated summaries and failure patterns when available. |
| Review | Submit, approve, reject, or annotate run evidence. |

## First review path

1. Start with the run status and item count.
2. Check the main metric summary.
3. Open failed or low-scoring rows before reading generated analysis.
4. Inspect traces only when the output or metric score does not explain the result.
5. Add review notes or corrections when the platform asks for human judgment.
6. Share the run link with teammates who have permission to view it.

## What not to expect here

App users do not need to know how the run was launched. If a run is missing, stale, or scoped incorrectly, collect the run name, project, owner, and approximate time, then send that context to the developer or operator responsible for the evaluation.
