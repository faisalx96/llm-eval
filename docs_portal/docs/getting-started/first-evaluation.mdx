# Run Your First Evaluation

Your first run should use the Python SDK. It should prove four things: your task function runs, your dataset shape is correct, your metric can score the output, and qym writes artifacts you can inspect.

## Python SDK first run

Create a tiny CSV:

```csv title="examples/qa.csv"
id,question,answer,topic
1,"What is 2 + 2?","4","math"
2,"What color is the sky on a clear day?","blue","general"
```

Run the evaluation from Python:

```python title="first_eval.py"
from qym import Evaluator
from qym.core.dataset import CsvDataset


def answer_question(question: str) -> str:
    # Replace this with your LLM call once the qym loop is working.
    if "2 + 2" in question:
        return "4"
    return "blue"


dataset = CsvDataset(
    "examples/qa.csv",
    input_col="question",
    expected_col="answer",
    id_col="id",
    metadata_cols=["topic"],
)

result = Evaluator(
    task=answer_question,
    dataset=dataset,
    metrics=["exact_match"],
    config={
        "run_name": "first-python-eval",
        "task_name": "answer-question",
        "max_concurrency": 2,
        "max_retries": 0,
        "run_metadata": {"owner": "docs", "suite": "smoke"},
    },
).run(show_tui=False)

print("run", result.run_name)
print("items", result.total_items)
print("success_rate", result.success_rate)
print("artifact", result.last_saved_path)
```

Run it:

```bash
python first_eval.py
```

## What each part does

| Part | What it controls | Why it matters |
|------|------------------|----------------|
| `CsvDataset(...)` | CSV path, input column, expected output column, ID column, metadata columns. | Keeps the first run local, stable, and inspectable. |
| `task=answer_question` | The Python function being evaluated. | This is the implementation under test. |
| `metrics=["exact_match"]` | The scoring strategy. | Deterministic metrics are easiest to debug first. |
| `run_name` | Human-readable run name. | Makes artifacts and platform runs easier to find. |
| `task_name` | Stable task identity. | Prevents auto-derived names from changing when code moves. |
| `max_concurrency` | Number of items evaluated concurrently. | Start low, then tune once providers and metrics are stable. |
| `max_retries` | Task retries after failure. | For a smoke test, fail fast instead of hiding errors. |
| `run_metadata` | Non-secret tags stored with results. | Use for prompt version, job ID, dataset version, owner, and release. |
| `show_tui=False` | Disables terminal UI. | Useful for notebooks, scripts, services, and tests. |

## Add platform streaming

Once local artifacts look correct, stream the same run to the platform:

```bash
export QYM_BASE_URL=https://qym.example.com
export QYM_API_KEY=<platform-api-key>
```

```python
result = Evaluator(
    task=answer_question,
    dataset=dataset,
    metrics=["exact_match"],
    config={
        "run_name": "first-platform-eval",
        "platform_url": "https://qym.example.com",
        # Prefer env var for real secrets. This explicit field is useful in services.
        "platform_api_key": "<platform-api-key>",
    },
).run(show_tui=False)
```

Platform streaming creates a platform run, streams item events and metrics, and still writes local artifacts. If streaming is unavailable, debug the local run first.

## Add progress for your wrapper

Use `progress_callback` when another service, UI, queue worker, or notebook needs progress updates.

```python
from qym import Evaluator, ProgressSnapshot


def on_progress(snapshot: ProgressSnapshot) -> None:
    if snapshot.event in {"run_start", "item_complete", "run_complete"}:
        print(snapshot.event, snapshot.finished, "/", snapshot.total_items)


result = Evaluator(
    task=answer_question,
    dataset=dataset,
    metrics=["exact_match"],
    progress_callback=on_progress,
).run(show_tui=False)
```

Progress callbacks are local SDK events. They do not replace platform streaming.

## What to inspect

1. `result.total_items` equals the dataset size.
2. `result.success_rate` matches your expectations.
3. The saved artifact exists under `qym_results/`.
4. Failed rows are easy to identify and reproduce manually.
5. Metadata includes only non-secret context.
6. Platform runs appear only after credentials are set.

:::warning Do Not Scale A Mystery
If the first run only works because of hidden shell state, hardcoded credentials, or an unclear dataset shape, stop and fix that before adding models, judges, platform streaming, or parallelism.
:::
