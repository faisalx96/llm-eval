# Concepts

qym becomes easier to use once the mental model is explicit. The generated concept pages in this section keep the explanations stable while the implementation evolves.

## High-Level Model

qym is built around a repeatable evaluation loop:

```text
task + dataset + metrics -> run -> results -> review -> comparison -> improvement
```

The SDK executes the loop. The CLI automates it from the shell. The platform stores, reviews, compares, and analyzes runs.

## Core Concepts

| Concept | Meaning |
|---------|---------|
| Task | The function, agent, prompt, or workflow being evaluated. |
| Dataset | The set of inputs, expected outputs, and metadata. |
| Item | One row or example from a dataset. |
| Metric | A deterministic, custom, or judge-based scoring function. |
| Run | One execution of a task against a dataset with a metric set. |
| Result | The per-item outputs, scores, errors, traces, and aggregate metrics. |
| Trace | Instrumentation data that explains what happened inside an item execution. |
| Platform stream | Live SDK events sent to qym platform for shared visibility. |
| Review correction | Human or AI-assisted annotations for root cause, solution, and approval. |

## Detailed Behavior

A qym run can be local-only or platform-visible.

Local-only:

- Runs task and metrics.
- Saves local artifacts.
- Can be uploaded later.

Platform-visible:

- Creates a platform run.
- Streams item, metric, trace, heartbeat, and completion events.
- Appears in dashboards, comparison, analysis, and review workflows.

Review and approval are platform workflows layered on top of run results. They do not change how the SDK executes the original evaluation, but they do add operational state such as DRAFT, SUBMITTED, APPROVED, or REJECTED.

## For Developers

Start from the workflow you are building:

| Workflow | Read |
|----------|------|
| Embed evaluation in Python | [Python API](/sdk/python-api) |
| Run from CI or shell | [CLI](/cli) |
| Stream to platform | [Platform Streaming](/sdk/platform-streaming) |
| Build direct API integration | [API Workflows](/api/workflows) |
| Deploy platform | [Deploy & Operate](/deploy-operate) |

Keep these boundaries clear:

- SDK progress callbacks are local to the SDK process.
- Platform streaming is the shared dashboard ingestion path.
- Saved artifacts are the durable local fallback.
- Review corrections are post-run platform annotations.

For review and governance concepts, read [Review And Approval Workflow](/concepts/review-approval).
