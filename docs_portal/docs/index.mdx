## App users

App users work in a deployed qym web application. They do not need Python packages, terminal commands, repository paths, or environment variables.

Start here when you need to:

- find runs and understand their status;
- inspect item-level outputs, expected values, metrics, and traces;
- compare runs before approving a change;
- review, approve, reject, or annotate results;
- troubleshoot missing runs, stale progress, or access problems.

## Developers

Developers build evaluations and integrations with qym. The developer path assumes you install qym from PyPI into your own application, notebook, worker, CI job, or service.

<CommandBlock

The developer docs cover `Evaluator`, datasets, metrics, custom judges, progress callbacks, observers, wrapper patterns, local artifacts, platform streaming, CLI automation, and direct API integration.

## Operators & contributors

Operators run the shared platform. Contributors modify qym itself.

Use this path for production deployment, auth, secrets, database configuration, upgrades, air-gapped behavior, and repository contribution workflows.

## Read in this order

1. [App Users](/app-users) if you only use the deployed qym web app.
2. [Developers](/getting-started) if you build evaluations with the SDK, API, CLI, observers, or wrappers.
3. [Operators & Contributors](/deploy-operate) if you deploy qym or work inside the repository.
