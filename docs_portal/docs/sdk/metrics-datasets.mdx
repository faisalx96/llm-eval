# Metrics And Datasets

The quality of a qym run depends more on dataset and metric discipline than on how much code you wrote around the evaluator.

## High-Level Model

Datasets define what gets tested. Metrics define how outputs are judged.

```text
dataset item
  input -----------> task -----------> output
  expected --------------------------> metric
  metadata --------------------------> filtering, grouping, analysis
```

Start with a small dataset and deterministic metric before adding judge metrics or large-scale concurrency.

## Detailed Behavior

## Dataset Choices

- Remote dataset: use this when teams share a single evaluation set and want consistent replay.
- Local CSV: use this for offline work, fast local iteration, and air-gapped execution.

### CSV Dataset

Use `CsvDataset` when your evaluation data lives in a local file.

```python
from qym import CsvDataset, Evaluator

dataset = CsvDataset(
    "qa.csv",
    input_col="question",
    expected_col="answer",
)

results = Evaluator(
    task=my_task,
    dataset=dataset,
    metrics=["exact_match"],
).run()
```

Typical CSV:

```csv
question,answer,difficulty,domain
What is 2+2?,4,easy,math
What is qym?,An evaluation framework,medium,llm-eval
```

Use metadata columns when you want breakdowns by domain, difficulty, product area, prompt version, or customer segment.

### Langfuse Dataset

Use a Langfuse dataset name when teams already maintain shared evaluation sets there:

```python
results = Evaluator(
    task=my_task,
    dataset="production-qa-regression",
    metrics=["exact_match"],
).run()
```

Langfuse datasets require Langfuse credentials. CSV datasets do not.

## Metric Choices

- Deterministic metrics: start here for exactness, containment, and simple regressions.
- Custom metrics: use when task output is structured or domain-specific.
- Judge metrics: use when the baseline loop already works and you need semantic scoring.

:::tip Good First Metric Set
Use one deterministic metric and one qualitative metric only after you understand what a good and bad item looks like manually.
:::

### Built-In Metrics

Use built-ins by name:

```python
metrics=["exact_match", "contains", "fuzzy_match"]
```

Use these for smoke tests, regression checks, and cases where expected output is clear.

### Custom Metrics

Custom metrics are Python callables. Keep them deterministic and easy to debug.

```python
def has_citation(output, expected=None, input_data=None):
    return 1.0 if "[" in str(output) and "]" in str(output) else 0.0

results = Evaluator(
    task=my_task,
    dataset=my_dataset,
    metrics=[has_citation],
).run()
```

Return a number, boolean, or richer metric result shape when you need metadata. Use metadata for explanations, labels, thresholds, or intermediate values that should appear in results.

### Judge Metrics

Judge metrics use an LLM to score outputs semantically. Add them after the task and dataset are already working with deterministic metrics.

Typical setup:

```bash
export QYM_JUDGE_MODEL=gpt-4o-mini
export QYM_JUDGE_API_KEY=<provider-key>
```

Then include judge metric names:

```python
metrics=["exact_match", "relevance", "correctness_llm"]
```

## For Developers

### Dataset Authoring Checklist

- Include stable item IDs when possible.
- Keep `input` and `expected` columns explicit.
- Add metadata columns for slices you will actually review.
- Keep a tiny 5-10 row dataset for local smoke tests.
- Keep a larger regression dataset for CI or release gates.
- Avoid mixing unrelated task types in one dataset.

### Metric Authoring Checklist

- Start with a deterministic metric.
- Make custom metrics tolerate `None` and unexpected output types.
- Return metadata when a metric failure needs explanation.
- Avoid network calls in custom metrics unless the metric is intentionally a judge.
- Keep judge prompts versioned and test them on a small set first.

### Common Failure Modes

| Symptom | Likely Cause | Fix |
|---------|--------------|-----|
| Metric always fails | Output shape does not match metric expectation. | Print a few outputs and adjust metric parsing. |
| CSV run cannot load | Wrong column names or malformed CSV. | Check `input_col`, `expected_col`, and encoding. |
| Judge metric errors | Missing provider configuration. | Set `QYM_JUDGE_MODEL` and API key env vars. |
| Good outputs score poorly | Metric is too strict or expected output is underspecified. | Add semantic judge or improve expected values. |
