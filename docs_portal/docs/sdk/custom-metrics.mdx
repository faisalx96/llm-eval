# Custom Metrics

Use custom metrics when built-in string metrics are too generic for your task. A custom metric is a Python callable that scores one task output.

## High-Level Model

```text
output + expected + input/context + task metadata -> metric function -> score + metadata
```

Custom metrics are best for deterministic rules:

- JSON validity
- field-level checks
- citation requirements
- tool-call correctness
- schema adherence
- domain-specific thresholds

Use judge metrics when scoring requires semantic interpretation by an LLM.

## Detailed Behavior

### Minimal Metric

```python
def has_answer(output, expected=None):
    return 1.0 if str(output).strip() else 0.0

results = Evaluator(
    task=my_task,
    dataset=my_dataset,
    metrics=[has_answer],
).run()
```

Metric names are derived from function names unless you register or wrap them differently.

### Return Types

qym accepts several return shapes.

| Return Type | Meaning |
|-------------|---------|
| `bool` | Converted to `1.0` or `0.0`. |
| `int` / `float` | Used as numeric score. |
| `dict` with `score` | Score plus optional metadata. |
| `MetricResult` | Structured score with label, explanation, kind, direction, metadata. |

### Dict Result

```python
def citation_score(output, expected=None):
    has_citation = "[" in str(output) and "]" in str(output)
    return {
        "score": 1.0 if has_citation else 0.0,
        "metadata": {
            "has_citation": has_citation,
            "rule": "square-bracket citation required",
        },
    }
```

Metadata is saved to artifacts and can appear in platform item details.

### Task Metadata

Tasks can pass hidden details to metrics by returning a qym task-output envelope:

```python
def rag_task(question):
    docs = retrieve(question)
    answer = generate_answer(question, docs)
    return {
        "output": answer,
        "metadata": {"retrieved_context": docs},
    }

def faithfulness(output, expected=None):
    docs = output["metadata"]["retrieved_context"]
    return judge_faithfulness(output["output"], docs)
```

Only the envelope's `output` field is treated as the visible task output. Custom metrics receive the full envelope as their `output` argument, so they can read hidden task details from `output["metadata"]`. Dict task returns that do not contain exactly `output` and `metadata` are rejected as malformed task outputs.

### MetricResult

```python
from qym.metrics.result import MetricResult

def json_validity(output, expected=None):
    try:
        json.loads(output)
        return MetricResult(
            score=1.0,
            label="valid",
            explanation="Output is valid JSON.",
            metadata={"parser": "json.loads"},
        )
    except Exception as exc:
        return MetricResult(
            score=0.0,
            label="invalid",
            explanation=str(exc),
            metadata={"parser": "json.loads"},
        )
```

### Async Metrics

Use async metrics only when the metric must call an async dependency.

```python
async def policy_check(output, expected=None):
    result = await policy_client.check(str(output))
    return {"score": 1.0 if result.allowed else 0.0, "metadata": result.details}
```

Use `metric_timeout` in SDK config to prevent one metric from blocking the run indefinitely.

## For Developers

### Signature Guidance

Keep metric signatures permissive when possible:

```python
def my_metric(output, expected=None, input_data=None, metadata=None):
    ...
```

Use `output["metadata"]` for task-output metadata from `{"output": ..., "metadata": ...}`. Use `item_metadata` when the metric needs dataset row metadata. Metrics should tolerate missing optional values.

### Registering Metrics

For reusable metrics, register them with qym's metric registry in your package initialization code.

```python
from qym.metrics.registry import register_metric

register_metric("has_citation", citation_score)
```

Then use by name:

```python
metrics=["has_citation"]
```

### Testing Metrics

Test metrics outside qym first:

```python
def test_citation_score():
    assert citation_score("Answer [1]")["score"] == 1.0
    assert citation_score("Answer")["score"] == 0.0
```

Then run a 5-row qym smoke dataset before adding the metric to a large regression suite.

### Common Mistakes

| Mistake | Impact | Fix |
|---------|--------|-----|
| Raising exceptions for normal bad output | Item may be marked as metric failure instead of low score. | Return score `0.0` with metadata explanation. |
| Returning strings as scores | Wrapped as score `0.0`. | Return numeric score or `MetricResult`. |
| Network calls without timeout | Run can stall. | Use async client and `metric_timeout`. |
| Hidden global state | Non-reproducible scores. | Pass config explicitly or store stable metadata. |
