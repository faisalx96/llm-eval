# Trace Integration

Traces explain what happened inside an evaluation item. They are most useful for RAG, agents, tool calls, and multi-step LLM workflows.

## High-Level Model

qym can connect three trace surfaces:

| Surface | Purpose |
|---------|---------|
| SDK spans | Local OpenTelemetry spans around evaluation, task, metrics, and instrumented LLM calls. |
| Platform trace viewer | Embedded trace and span data stored with qym runs. |
| Langfuse | External trace/project view when Langfuse credentials and datasets are used. |

Traces are diagnostic evidence. Metrics tell you that something failed; traces help explain why.

## Detailed Behavior

### OpenTelemetry

`otel_enabled` defaults to `True`. If supported instrumentors are installed, qym captures spans for supported LLM/framework calls.

```python
Evaluator(
    task=my_task,
    dataset=my_dataset,
    metrics=["exact_match"],
    config={"otel_enabled": True},
).run()
```

Disable only when tracing overhead or provider behavior is causing problems:

```python
config={"otel_enabled": False}
```

### Platform Trace Streaming

When platform streaming is enabled, qym sends `span_completed` events to the platform. The platform stores span trees and exposes trace views from run items.

Useful fields include:

- `trace_id`
- `span_id`
- `parent_span_id`
- span name and kind
- start/end time
- duration
- status
- span attributes

### Langfuse

When Langfuse credentials are configured and the run uses Langfuse datasets, qym links dataset run items to traces where possible.

Relevant env vars:

```bash
LANGFUSE_PUBLIC_KEY=...
LANGFUSE_SECRET_KEY=...
LANGFUSE_HOST=https://cloud.langfuse.com
```

### Phoenix

Phoenix export can be enabled separately:

```python
config={
    "phoenix_enabled": True,
    "phoenix_endpoint": "http://localhost:6006/v1/traces",
}
```

## For Developers

### Debugging Missing Traces

Check:

- `otel_enabled` is not disabled.
- The relevant OpenTelemetry instrumentor is installed.
- The LLM/framework call happens inside the task execution.
- Platform credentials are configured if you expect traces in qym platform.
- Langfuse credentials are configured if you expect Langfuse links.
- The item did not fail before trace setup.

### Trace-Friendly Task Code

Keep task code structured enough for traces to be useful:

```python
async def answer_question(question, context, model_name="gpt-4o-mini"):
    prompt = build_prompt(question, context)
    response = await llm_client.chat.completions.create(
        model=model_name,
        messages=[{"role": "user", "content": prompt}],
    )
    return response.choices[0].message.content
```

Avoid hiding all work behind opaque subprocesses or remote job IDs unless you also attach trace IDs to your own logs.

### Common Mistakes

| Mistake | Impact | Fix |
|---------|--------|-----|
| Expecting traces without platform credentials | No qym platform trace view. | Set `QYM_BASE_URL` and `QYM_API_KEY`. |
| Expecting Langfuse links for CSV-only runs | Langfuse dataset linking may not exist. | Use Langfuse datasets or rely on qym platform trace viewer. |
| Disabling OTEL globally | Missing spans. | Leave `otel_enabled=True` unless debugging overhead. |
| Tool output is malformed | Span may be marked error. | Inspect trace viewer and task output. |
