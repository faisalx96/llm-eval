# Getting Started

This section is for developers building with qym. Start here when you want to install the PyPI SDK, run evaluations from Python, add datasets and metrics, stream to the platform, or automate the same workflow from a shell.

If you only use the deployed qym web app, start with [App Users](/app-users).

## First mental model

```text
dataset item -> Python task function -> output -> metrics -> artifacts
                                             -> optional progress callback
                                             -> optional platform stream
                                             -> optional traces
```

Start with a local CSV and deterministic metric. Add Langfuse, judge metrics, platform streaming, tracing, multi-model runs, and CI after the baseline is clear.

## What you can do from Python

The SDK can:

- run sync and async task functions;
- pass dictionary dataset inputs into matching Python parameters;
- evaluate local `CsvDataset` objects or Langfuse dataset names;
- use built-in metric names and custom metric callables;
- configure concurrency, metric concurrency, timeouts, retries, checkpoints, output paths, metadata, git metadata, model routing, and tracing;
- run one model, many models, or many run specs;
- save local artifacts and resume from checkpoints;
- stream to the platform when `QYM_BASE_URL` and `QYM_API_KEY` are configured;
- emit `ProgressSnapshot` updates for custom wrappers;
- attach OpenTelemetry spans and export to qym and Phoenix when configured.

## What you can do from the CLI

The CLI can:

- launch a run from a Python file and function;
- use a Langfuse dataset name or CSV dataset flags;
- pass JSON config through `--config`;
- select one or many models with `--model`;
- resume from a checkpoint with `--resume-from`;
- save JSON output with `--output`;
- emit agent-friendly JSON with global `--json`;
- inspect, compare, analyze, and upload runs through platform commands.

Use the CLI after the Python task and dataset contracts are understood. It is strongest in CI, shell scripts, and agent workflows.

## Before you start

Decide these explicitly:

| Decision | Python-first recommendation | Why |
|----------|-----------------------------|-----|
| Dataset | Start with `CsvDataset`. | It removes remote credentials from the first loop. |
| Task | Write a small function with a typed input shape. | Metrics and debugging are easier when the contract is simple. |
| Metrics | Start with deterministic metrics. | Judge metrics add provider configuration and latency. |
| Platform | Add after local artifacts are correct. | Streaming should not hide task or metric problems. |
| Concurrency | Start low, then scale. | Provider rate limits and custom metrics fail noisily under premature concurrency. |
| CLI | Use as an equivalent launcher after Python works. | The SDK is the implementation surface; CLI is an execution wrapper. |

## Required and optional environment

For local CSV SDK runs, no platform or Langfuse credentials are required.

For platform streaming:

```bash
export QYM_BASE_URL=http://localhost:8000
export QYM_API_KEY=<platform-api-key>
```

For Langfuse datasets:

```bash
export LANGFUSE_PUBLIC_KEY=...
export LANGFUSE_SECRET_KEY=...
export LANGFUSE_HOST=https://cloud.langfuse.com
```

For LLM judge metrics:

```bash
export QYM_JUDGE_MODEL=gpt-4o-mini
export QYM_JUDGE_API_KEY=<provider-key>
export QYM_JUDGE_BASE_URL=https://api.openai.com/v1
```
