# Running Evaluations From The CLI

Use `qym run create` when a shell command is the right boundary. The CLI is secondary to the Python SDK: it loads a Python task function, builds an SDK dataset/config, runs `Evaluator`, saves artifacts, and optionally streams to the platform.

## Start From The Python Equivalent

This Python call:

```python
from qym import Evaluator
from qym.core.dataset import CsvDataset

result = Evaluator(
    task=answer_question,
    dataset=CsvDataset(
        "datasets/smoke.csv",
        input_col="question",
        expected_col="answer",
        id_col="id",
        metadata_cols=["topic"],
    ),
    metrics=["exact_match"],
    config={
        "run_name": "ci-smoke",
        "task_name": "support-rag",
        "max_concurrency": 4,
        "max_retries": 1,
    },
).run(show_tui=False)
```

maps to this CLI command:

## Complete Single-Run Shape

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --csv-input-col question \
  --csv-expected-col answer \
  --csv-id-col id \
  --csv-metadata-cols topic,source \
  --metrics exact_match,fuzzy_match \
  --model gpt-4o-mini \
  --task-name support-rag \
  --config '{"run_name":"manual-smoke","timeout":120,"metric_timeout":30,"max_concurrency":4}' \
  --platform-url http://localhost:8000 \
  --platform-api-key "$QYM_API_KEY" \
  --ui-port 0
```

Every flag is optional except the task, dataset, and metric requirements. Use exactly one dataset source: `--dataset` or `--dataset-csv`.

## Dataset Modes

### Local CSV

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --csv-input-col question \
  --csv-expected-col answer \
  --metrics exact_match
```

Use CSV for first runs, offline workflows, CI smoke tests, and air-gapped execution.

### Langfuse dataset

```bash
export LANGFUSE_PUBLIC_KEY=...
export LANGFUSE_SECRET_KEY=...
export LANGFUSE_HOST=https://cloud.langfuse.com

qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset production-qa-regression \
  --metrics exact_match,relevance
```

Use Langfuse dataset names when the dataset is already managed remotely.

## Configuration Through `--config`

`--config` accepts JSON and maps to `EvaluatorConfig`.

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match \
  --config '{
    "run_name": "ci-smoke",
    "max_concurrency": 4,
    "max_metric_concurrency": 1,
    "timeout": 120,
    "metric_timeout": 30,
    "max_retries": 1,
    "output_dir": "qym_results/ci",
    "checkpoint_enabled": true,
    "checkpoint_flush_each_item": true,
    "run_metadata": {
      "source": "ci",
      "suite": "smoke"
    }
  }'
```

Common `--config` fields:

| Field | Why use it |
|-------|------------|
| `run_name` | Stable artifact/platform label. |
| `max_concurrency` | Rate-limit and throughput control. |
| `max_metric_concurrency` | Prevent metrics from overwhelming providers. |
| `timeout` | Bound task calls. |
| `metric_timeout` | Bound metric calls. |
| `max_retries` | Retry transient task failures. |
| `output_dir` | Separate local artifacts by suite/job. |
| `checkpoint_enabled` | Recover interrupted runs. |
| `resume_rerun_errors` | Reattempt failed rows during resume. |
| `run_metadata` | Store non-secret labels. |
| `otel_enabled` | Enable or disable tracing instrumentation. |
| `phoenix_enabled` | Export traces to Phoenix when configured. |

See [SDK Configuration](/sdk/configuration) for the complete field table.

## Platform Streaming

When platform credentials are configured, CLI runs stream to the platform and still save local artifacts.

```bash
export QYM_BASE_URL=http://localhost:8000
export QYM_API_KEY=<platform-api-key>
```

Or pass them explicitly:

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match \
  --platform-url http://localhost:8000 \
  --platform-api-key "$QYM_API_KEY"
```

## Multi-Model

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match \
  --model gpt-4o-mini,gpt-4.1-mini
```

Use this only when the task, dataset, and metrics are the same and only model routing changes.

## Multi-Run Config

Use `--runs-config` when tasks, datasets, metrics, outputs, or config differ by run.

```json title="experiments.json"
[
  {
    "name": "baseline",
    "task_file": "eval_task.py",
    "task_function": "baseline_answer",
    "dataset_csv": "datasets/smoke.csv",
    "metrics": ["exact_match"],
    "config": {
      "run_name": "baseline-smoke",
      "max_concurrency": 4
    },
    "output_path": "qym_results/baseline.csv"
  },
  {
    "name": "candidate",
    "task_file": "eval_task.py",
    "task_function": "candidate_answer",
    "dataset_csv": "datasets/smoke.csv",
    "metrics": ["exact_match"],
    "config": {
      "run_name": "candidate-smoke",
      "max_concurrency": 4
    },
    "output_path": "qym_results/candidate.csv"
  }
]
```

```bash
qym run create --runs-config experiments.json
```

## Resume

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match \
  --resume-from qym_results/checkpoints/support-rag.csv
```

To rerun errored rows during resume, use:

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match \
  --resume-from qym_results/checkpoints/support-rag.csv \
  --config '{"resume_rerun_errors":true}'
```

## Automation

Use global `--json` when another system consumes output:

```bash
qym --json run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match \
  --no-progress
```

Rules:

- JSON goes to stdout.
- Human status and errors go to stderr.
- Use exit codes for control flow.
- Run `qym config check --json` before platform-dependent steps.

## Common Failure Modes

| Failure | Cause | Fix |
|---------|-------|-----|
| Task import fails | Wrong `--task-file` or `--task-function`. | Import the function in Python first. |
| CSV columns missing | Wrong CSV flags. | Match `--csv-input-col`, `--csv-expected-col`, and metadata names to the file. |
| Langfuse dataset fails | Missing Langfuse credentials or wrong dataset name. | Set Langfuse env vars and verify the dataset. |
| Judge metric fails before scoring | Missing judge model or key. | Set `QYM_JUDGE_MODEL` and `QYM_JUDGE_API_KEY`. |
| Platform streaming fails | Missing URL/key or auth issue. | Run `qym config check --json`. |
| Automation parses unstable text | Human stderr output was parsed. | Use global `--json`. |
