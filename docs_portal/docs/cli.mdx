# CLI

The qym CLI is the secondary interface. It is not the main implementation model for developers; the Python SDK is. Use the CLI when you need shell execution, CI steps, agent workflows, or platform inspection without writing additional Python glue.

## High-Level Model

The CLI wraps SDK and platform workflows:

```text
Python SDK model  -> task + dataset + metrics + EvaluatorConfig
CLI run command   -> task file + task function + dataset flags + metrics + JSON config
Platform commands -> list/get/failed/compare/analyze/upload/config
```

Use the SDK for application code and services. Use the CLI for automation boundaries.

## What The CLI Can Do

| Command | What it does | Primary use |
|---------|--------------|-------------|
| `qym run create` | Execute an evaluation from a Python task file. | CI, shell, agents, manual runs. |
| `qym run create --runs-config` | Execute multiple run specs from YAML/JSON. | Batch comparisons and automation. |
| `qym run list` | List platform runs. | Inspection and follow-up automation. |
| `qym run get` | Fetch one platform run. | Debugging and reporting. |
| `qym run failed` | Fetch failed items for a run. | Triage and repair. |
| `qym run compare` | Compare two platform runs. | Regression analysis. |
| `qym run tasks` | List known platform task names. | Discovery and filtering. |
| `qym metric list` | List available metrics. | Metric discovery. |
| `qym analyze run` | Run AI-assisted analysis for a run. | Review workflows. |
| `qym analyze summary` | Fetch analysis summary. | Reporting and dashboards. |
| `qym config show` | Show resolved environment. | Local debugging. |
| `qym config check` | Validate platform connectivity. | CI preflight and auth debugging. |
| `qym dashboard` | Open platform dashboard. | Operator convenience. |
| `qym submit` | Upload saved artifacts. | Offline-to-platform workflows. |

The generated [CLI Reference](/cli/reference) is the exhaustive command tree. This page explains how to use that tree correctly.

## `qym run create` Surface

| Flag | Required | Meaning |
|------|----------|---------|
| `--task-file` | Yes for single run | Python file containing the task function. |
| `--task-function` | Yes for single run | Function name inside the task file. |
| `--dataset` | Exactly one of dataset inputs | Langfuse dataset name. |
| `--dataset-csv` | Exactly one of dataset inputs | Local CSV path. |
| `--csv-input-col` | CSV only | CSV input column; defaults to `input`. |
| `--csv-expected-col` | CSV only | CSV expected output column; defaults to `expected_output`; empty disables expected output. |
| `--csv-id-col` | CSV only | Stable item ID column. |
| `--csv-metadata-cols` | CSV only | Comma-separated metadata columns. |
| `--metrics` | Yes for single run | Comma-separated metric names. |
| `--model` | Optional | Single model or comma-separated models. |
| `--task-name` | Optional | Stable task identity. |
| `--config` | Optional | JSON string merged into `EvaluatorConfig`. |
| `--platform-url` | Optional | Overrides `QYM_BASE_URL`. |
| `--platform-api-key` | Optional | Overrides `QYM_API_KEY`. |
| `--resume-from`, `--run-file` | Optional | Resume from checkpoint or run file. |
| `--quiet`, `-q` | Optional | Only print final summary. |
| `--no-progress` | Optional | Disable progress bar. |
| `--no-ui` | Optional | Disable local web UI/table output. |
| `--ui-port` | Optional | Local UI port; `0` means auto. |
| `--no-open` | Optional | Do not open browser automatically. |
| `--output` | Optional | Save single-model JSON output. |
| `--runs-config` | Optional | Multi-run YAML/JSON config. |
| `--git-branch` | Optional | Override git branch metadata. |
| `--git-commit` | Optional | Override git commit metadata. |
| global `--json` | Optional | Machine-readable stdout, human logs on stderr. |

## CLI To SDK Mapping

The CLI builds these SDK objects internally:

```text
--dataset-csv + CSV flags -> CsvDataset(...)
--dataset                  -> Langfuse dataset name
--metrics                  -> metrics=[...]
--model                    -> Evaluator(model=...)
--config                   -> EvaluatorConfig(...)
--task-name                -> config.task_name
--platform-url             -> config.platform_url
--platform-api-key         -> config.platform_api_key
--resume-from              -> config.resume_from
```

If behavior is unclear, reproduce the same run in Python first. The SDK gives you direct access to the dataset object, task callable, config object, result object, and progress callbacks.

## Examples

### CSV run

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --csv-input-col question \
  --csv-expected-col answer \
  --csv-id-col id \
  --csv-metadata-cols topic,source \
  --metrics exact_match,fuzzy_match \
  --task-name support-rag \
  --config '{"run_name":"support-rag-smoke","max_concurrency":4,"max_retries":1}'
```

### Langfuse dataset run

```bash
export LANGFUSE_PUBLIC_KEY=...
export LANGFUSE_SECRET_KEY=...
export LANGFUSE_HOST=https://cloud.langfuse.com

qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset support-smoke \
  --metrics exact_match \
  --config '{"run_name":"langfuse-smoke"}'
```

### Platform streaming

```bash
export QYM_BASE_URL=http://localhost:8000
export QYM_API_KEY=<platform-api-key>

qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match
```

### JSON automation

```bash
qym --json run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match
```

### Resume

```bash
qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --metrics exact_match \
  --resume-from qym_results/checkpoints/support-rag.csv
```

## Environment Variables

| Env var | CLI use |
|---------|---------|
| `QYM_BASE_URL` | Platform commands and streaming. |
| `QYM_API_KEY` | Platform authentication. |
| `LANGFUSE_PUBLIC_KEY` | Langfuse dataset loading. |
| `LANGFUSE_SECRET_KEY` | Langfuse dataset loading. |
| `LANGFUSE_HOST` | Langfuse host. |
| `QYM_JUDGE_MODEL` | Judge metrics. |
| `QYM_JUDGE_API_KEY` or `OPENAI_API_KEY` | Judge metric provider auth. |
| `QYM_JUDGE_BASE_URL` or `OPENAI_BASE_URL` | OpenAI-compatible judge endpoint. |

## Exit Codes

| Code | Meaning |
|------|---------|
| `0` | Success. |
| `1` | Failure. |
| `2` | Usage error or low success threshold warning in run creation. |
| `3` | Not found. |
| `4` | Auth denied. |
| `5` | Conflict. |

## For Developers

Use the CLI when:

- the caller is CI, a shell script, or an agent;
- you need stable JSON stdout and human logs on stderr;
- you want to inspect platform runs without writing HTTP code;
- you need to upload artifacts from an offline run.

Use Python instead when:

- the evaluation is part of a service;
- task dependencies are already Python objects;
- you need progress callbacks;
- you need custom observers;
- you need direct result object access;
- you need complex dataset construction before evaluation.
