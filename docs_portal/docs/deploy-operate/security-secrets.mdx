# Security And Secrets

Use this page when deploying qym or running SDK/CLI clients in environments that handle real credentials, customer data, or production evaluation artifacts.

## High-Level Model

qym has several secret classes:

| Secret | Used By |
|--------|---------|
| `QYM_API_KEY` | SDK/CLI ingestion into platform. |
| `QYM_ADMIN_BOOTSTRAP_TOKEN` | First admin bootstrap. |
| `QYM_AUTH_SESSION_SECRET` | Browser session signing. |
| `QYM_LLM_CONFIG_ENCRYPTION_KEY` | Encrypting stored user LLM configs. |
| Langfuse keys | Langfuse datasets and trace linking. |
| Judge/provider keys | LLM judge metrics and AI analysis. |
| Database URL/password | Platform persistence. |

Secrets must not appear in run metadata, item metadata, result artifacts, logs, screenshots, or docs examples.

## Detailed Behavior

### SDK / CLI Secrets

```bash
QYM_PLATFORM_URL=https://qym.example.com
QYM_API_KEY=...
LANGFUSE_PUBLIC_KEY=...
LANGFUSE_SECRET_KEY=...
QYM_JUDGE_MODEL=gpt-4o-mini
QYM_JUDGE_API_KEY=...
```

Use environment variables or secret managers. Do not hardcode keys in task files or metrics.

### Platform Secrets

```bash
QYM_DATABASE_URL=postgresql+psycopg2://...
QYM_AUTH_SESSION_SECRET=...
QYM_ADMIN_BOOTSTRAP_TOKEN=...
QYM_LLM_CONFIG_ENCRYPTION_KEY=...
```

Generate a Fernet key for `QYM_LLM_CONFIG_ENCRYPTION_KEY`:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### API Keys

API keys are created from the platform profile page or API surfaces. Tokens are shown once. Store them in a secret manager and rotate them when:

- a developer leaves
- a CI environment is compromised
- the token appears in logs
- scope or ownership changes

### Metadata Safety

Do not put secrets here:

```python
config={
    "run_metadata": {
        "api_key": "...",  # wrong
    }
}
```

Use metadata only for non-sensitive identifiers:

```python
config={
    "run_metadata": {
        "team": "search",
        "release": "2026-04-24",
        "prompt_version": "v17",
    }
}
```

## For Developers

### Local Development

Use a local `.env` file for development only. Keep `.env` gitignored.

```bash
QYM_PLATFORM_URL=http://localhost:8000
QYM_API_KEY=dev-token
```

### CI

- Store `QYM_API_KEY` as a CI secret.
- Avoid echoing env vars.
- Use `qym config check --json` to validate connectivity.
- Redact stderr logs before sharing externally.

### Production

- Use a managed secret store.
- Rotate platform API keys.
- Back up the database securely.
- Keep `QYM_LLM_CONFIG_ENCRYPTION_KEY` stable across restarts; losing it can make encrypted user LLM configs unreadable.
- Restrict platform admin endpoints behind auth and network controls.

### Common Mistakes

| Mistake | Impact | Fix |
|---------|--------|-----|
| Secret in run metadata | Leaks into platform UI and artifacts. | Use env vars and secret managers. |
| Rotating encryption key without migration | Stored configs become unreadable. | Plan rotation procedure. |
| Reusing one API key everywhere | Hard to audit and revoke. | Use per-user or per-project keys. |
| Committing `.env` | Credential leak. | Keep `.env` ignored and scan commits. |
